# 参赛者讲解速查

这份文件帮助参赛者核实、理解和演示作品；不能用来声称已经掌握尚未理解的内容。

## 一句话

PLUVIA 是城市雨洪教育实验室：同一场雨、同一个城市，比较改造前后差异，并在预算内搜索更好的设施布局。

## 必须讲清的五点

1. **数据是合成的。** 不是上海或其他真实城市的预测。参数与成本是示例，不可据此施工或避险。
2. **水量必须对得上。** 降雨总量 = 仍在地表的水 + 设施储水 + 入渗 + 河流/雨水口排走的水。残差是记账误差，不代表真实准确度。
3. **水如何流。** 每两个相邻网格交换水。水面高程（地面高程加水深）较高的一边向较低的一边流；流量考虑水深、坡度与粗糙度，并限制单步转移避免负数和振荡。
4. **优化器不是聊天模型。** 选择几个较湿且空间分散的位置，分别放设施并重算整场雨，比较每一元成本带来的目标改善，接受最好的一个，然后继续。它是贪心算法，不保证全局最优。
5. **AI 贡献要披露。** 设计、实现、测试、文档等大量内容由 OpenAI Codex 协助生成；作品运行不调用大模型。

## 技术问题准备

- 为什么用 Worker？优化器反复运行数值模拟，放到后台线程避免阻塞交互。
- 为什么还要基线？否则无法确定变化来自设施、不同降雨还是不同地形。成对反事实保持其他条件一致。
- 为什么设施类型不能乱放？透水铺装针对道路；花园和蓄水池需要空地或公园。
- A* 是什么？用已走代价和到终点的曼哈顿估计指导搜索。水深大于 15 cm 的网格在教学模型中不可通行。
- 为什么守恒还不够？原始模型虽守恒，但时间步过大导致棋盘格振荡，因此加水头差限幅使扩散稳定。
- 局限？合成场景、未校准、没有完整地下管网和回水、土壤参数简化、成本没有地方报价依据。

## 已测量的示例

34 项设施，成本 $176,500 / 预算 $180,000。90 mm/h 持续 60 分钟的脉冲降雨：峰值地表水约 7,951 → 7,612 m³，减少 4.3%。120 分钟季风减少约 6.0%，极端暴雨减少约 2.8%。不要将其描述为真实城市的防洪效果。
